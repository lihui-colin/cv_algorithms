2026-09-14。使用补齐后的 7 条 GT，直接按导出的正确模型标签关联，不再应用历史标签修正。
本轮没有修改生产匹配算法或默认参数。完整逐目标误差、输出位姿和输入 CSV SHA256 见
[halcon_parameter_measurements.json](halcon_parameter_measurements.json)。

## 方法

新增 `tests/halcon_parameter_probe.cpp`，构建目标为 `halcon_parameter_probe`。
它读取 HALCON 的两份参数 CSV，分别只对齐一组参数，然后对齐所有已导出的相关参数。
模板仍使用当前 PGM 和 mask，角度/尺度范围、最低层及精定位模式保持基线设置。
始终全图搜索，参考位姿不传入匹配器。参数数值相同不代表双方实现语义或梯度量纲完全相同。

最新导出：ring/nut 均为 4 层；低阈值 8/6，高阈值 16/8，min_size 4/10，
optimization 均为 none，angle_step 分别为 0.0404089/0.0446693 rad。
CSV 尚未包含实际 iso_scale_step、min_contrast、origin 或 subpixel，因而“全部对齐”仅指表中六项参数。

## 固定搜索结果、替换模板轮廓

为避免搜索差异干扰，从基线自动检出的 7 个位姿出发，只改变精定位模板点：

1. 直接使用导出的 HALCON 轮廓点位置与点数；法线、强度、权重取最近的原 C++ 模板点。
2. 保留 C++ 模板点数量、法线和权重，只将点位置投影到 HALCON 同条轮廓的相邻点线段上。

场景边缘、求解器和评分仍为 C++ 原实现，未使用 GT 初始化。
导出中没有 HALCON 法线/权重，故这不是完整 HALCON 模型替换；直接导入点法也改变了采样密度。
诊断保留全部基线实例，未重新做最终 NMS，因此下表的 7 个结果不代表独立召回测试。

| 精定位模板 | 7 个固定实例 RMSE px | 最大误差 px |
|---|---:|---:|
| 原 C++ 模板 | 0.300350 | 0.579015 |
| HALCON 点位置与点数 | 0.302750 | 0.590370 |
| C++ 点投影到 HALCON 轮廓 | 0.301366 | 0.584791 |

两个诊断的最终评分均大于 0.5，但均未改善整体 GT 误差。
尤其大 nut 的约 0.58px 偏差仍然存在。结果支持“只改变模板点位置不足以解决偏差”，
不支持断言模板误差完全为零，也不能证明剩余偏差全部来自场景边缘。

## 复现与下一步

```bash
cd shape_match_v1
bash scripts/build.sh
# 输出目录必须不存在，防止覆盖既有实验结果。
SHAPE_MATCH_NUM_THREADS=8 ./build/halcon_parameter_probe data results-halcon-ablation
python3 scripts/compare_gt.py results-halcon-ablation/baseline.csv \
  --reference data/reference/matching_results.csv --max-rmse 0.1 --max-error 0.2
```

当前基线精度门限预期失败；探针正常退出只表示实验执行成功，不表示精度或召回达标。
`runs.csv` 为单次搜索计时，不用于性能验收。

下一步应固定同一模板和初始位姿，检查场景边缘的法向残差、内外轮廓贡献、尺度约束及对应点取舍。
例如 GT #2 的尺度恰好为 0.8 下界，而当前输出约为 0.80546；这值得单独分析，但不能将该 GT 尺度硬编码回匹配器。
如需验证 HALCON 是否使用了不同的场景边缘/对应关系，还需相应观测数据；变换后的模型轮廓不能充当实际场景边缘。
现有坐标三位小数的舍入上界约 0.00071px，不能解释 0.3px 量级偏差。
